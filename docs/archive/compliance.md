## 三、本轮发现并补齐的缺口

### 缺口 1：没有数据访问 API（官方「基本要求」）

之前只有静态文件和站点，官方要求的 Restful 查询接口是缺的。新增 `src/app/serve_api.py`：

| 端点 | 作用 |
|---|---|
| `GET /api/stats` | 规模与分布 |
| `GET /api/skills?family=&q=` | 技能列表（按岗位数排序） |
| `GET /api/jobs?skills=&city=&family=&limit=` | 技能 AND 检索岗位 |
| `GET /api/gap?family=&have=` | 技能差距 |
| `GET /api/job/<doc_id>` | 单岗位详情 |

实测（本地 8765 端口）：

```
/api/stats                     → 4,865 岗 / 389 技能 / 66,689 三元组
/api/skills?family=算法&q=模型  → 9 项，大语言模型 1,540 岗
/api/jobs?skills=大语言模型,RAG&city=北京 → 240 个岗位
/api/gap?family=后端&have=Python,SQL     → 缺 Go(474)、Java(389)…
```

踩过一个坑：`BaseHTTPRequestHandler` 按 latin-1 解析请求行，中文参数会变乱码，已加 `latin-1 → utf-8` 回转。

文档：`docs/api.md`。

### 缺口 2：Schema 只有 TTL，没有 JSON-LD

官方推荐 JSON-LD。`package.py` 现在会从 `ontology.ttl` 自动导出 `ontology.jsonld`（rdflib，20 个节点），一并放进发布包。

### 缺口 3：作业提到 QA，但只做了搜索和挖掘

站点新增第 5 个页签「智能问答」，纯前端规则实现：

- 解析问句里的城市、岗位族、技能词
- 支持四类问题：某族要什么技能 / 某地+某技能有哪些岗位 / 技能差距 / 薪资（诚实回答「数据源不公布」）
- 答案附 5 个证据岗位与原文链接

实测：「北京要求 RAG 的岗位」→ 227 个，Top 技能 RAG 227、大语言模型 211、Agent 199…

### 缺口 4：PPT 没有分工页

课程明确要求 3–4 人一组，但原 14 页里没有一页讲分工。新增第 14 页「分工与协作」，列 4 人职责与产出物，并注明 3 人版如何合并。

### 缺口 5：应用页措辞过时

原写「一个站点三个功能」，实际已有五个页签。改为「四个功能（另有技能分类页签）」。

## 五、与平台已发布数据集的横向对照

除了对照要求，还抓了 200 个已发布数据集看"别人实际怎么发"（详见 `benchmark.md`）：

| 维度 | 平台现状 | 我们 |

| 资源数 | 中位数 2 | 8 |
| 有 Schema | 17% | 有，TTL + JSON-LD 两种 |

| notes 字数 | 中位数 164 / P90 513 | 664 |

据此做了两处**向平台惯例靠拢**的调整：简介 1,200 → 664 字；标签 6 → 4 个。

## 六、自查结论

课程五条要求全部满足；OpenKG 八条要求中七条满足、一条部分满足（数据互联）。

本轮之前，项目缺的是**官方明确要求、但我们漏掉的两项**：数据查询 API 与 JSON-LD 版 Schema——这两项如果不补，提交时数据集页的「数据访问API」资源项会是空的，审核方一眼能看出来。
